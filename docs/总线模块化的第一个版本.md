# 总线模块化的第一个版本

## 目标

把现有混合式总线/事件/持久化结构，收敛成下面这套模型：

- 一套统一消息入口：`lib/message_queue.js`
- 两种消息模式：
  - `transient`
  - `durable`
- 默认使用 `transient`
- 状态恢复只依赖 projection
- 实际落盘统一由 persist / writer 执行

## 第一版范围

这一版不是一次性全量完成最终架构，而是先完成运行主路径最关键的收口：

1. `runtime_bus` 被统一消息接口吸收
2. `sync` 的 command queue 改成 durable queue
3. `sync.job.updated` / `sync.state.snapshot_replaced` 保持 direct projection
4. `catalog` 从整包 snapshot 语义切成 entity batch 语义
5. `chat` 保持移除态，不参与迁移

### 3. Sync 的第一版迁移结果

文件：
- [sync_domain.js](/home/jb9802/.openclaw/workspace/app/bsv_market/sync_domain.js)

当前规则：
- durable：
  - `sync.command` queue
- transient/direct projection：
  - `sync.job.updated`
  - `sync.state.snapshot_replaced`

现在 `sync` 命令不再依赖旧的 `sync.command.*` 伪事件主路径：
- `enqueueCommand()` -> durable publish
- `claimNextCommand()` -> durable claim
- `markCommandFinished()` -> durable finish
- `releaseClaimedCommand()` -> durable release

projection 仍然保留：
- `sync_command_projection`
- `sync_job_state_projection`
- `sync_state`

含义：
- durable queue 是命令事实源
- projection 是读取/恢复视图

### 4. Catalog 的第一版迁移结果
