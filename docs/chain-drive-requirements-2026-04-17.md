# 链上网盘需求与开发计划

日期：2026-04-17

状态：需求已收敛，暂不实现

## 目标

为当前系统增加一个“链上网盘”模块，用于保存用户自己的加密目录结构和文件内容。

第一版目标：

- 文件内容先在服务器本地压缩、分块、加密，再写入链上
- 目录结构、目录名、文件名、文件索引也上链，并且同样加密
- 节点同步时只恢复当前用户自己的目录树和文件索引，不自动下载文件内容
- 下载时支持两条路径：
  - 下载到服务器本地指定目录并自动解压
  - 通过浏览器下载文件

一句话：

这是“用户自己的加密链上网盘”，不是公开共享网盘。

## 已确认的核心原则

### 1. 加密模型

- 服务器必须持有可用于解密网盘内容的密钥材料
- 钱包私钥或钱包口令不直接用于加密文件内容
- 钱包私钥或钱包口令只用于解锁或派生 `driveMasterKey`
- 真正的目录和文件内容使用 `driveMasterKey` 再派生出的密钥进行加密

推荐密钥链路：

- `wallet secret -> driveMasterKey`
- `driveMasterKey -> dirKey`
- `driveMasterKey -> fileKey`
- `fileKey -> chunk encryption key`

这意味着：

- 节点可以在后台同步时自动解密目录树和文件名
- 不要求用户每次打开网页都重新输入解密材料
- 这是“受信任服务器代用户加密/解密”的模型，不是浏览器零知识模型

### 2. 上传模型

- 用户在浏览器中选择文件或目录
- 浏览器通过 HTTP 将文件上传到项目所在服务器
- 服务器负责后续流程：
  - 先确保目录结构已存在并完成上链
  - 压缩
  - 分块
  - 加密
  - 上链
- Web 端必须支持大文件上传和上传进度显示

上传硬约束：

- 上传文件前，必须先确保目标目录链已经存在
- 必须先完成目录对象上链，再允许写入文件对象
- 不允许“先上传文件内容，后补目录结构”
- `drive_file.parentDirId` 必须引用一个已经确认存在的 `drive_dir`
- 如果目录对象未上链成功，文件上传必须失败

### 3. 下载模型

下载需要同时支持两条链路：

- 服务器本地恢复
  - 从链上下载文件内容到服务器本地指定目录
  - 下载完成后自动解压
  - 本地恢复出的目录结构与链上目录树一致
- 浏览器下载
  - 用户在网页中点击文件或目录
  - 服务器读取并解密文件内容后提供浏览器下载

### 4. 同步模型

- 链扫描阶段可以看全网事件
- 本地只持久化 `ownerWalletId == 当前钱包` 的网盘对象
- 其它用户的数据直接忽略
- 不进入本地索引
- 不进入缓存
- 不进入 UI

### 5. 目录树模型

目录和文件索引是分开的，但都属于目录树的一部分。

- 链上目录对象负责目录结构
- 链上文件对象负责文件名、父目录关系、文件元数据、内容引用
- 链上内容块对象只负责文件内容分片

用户浏览网盘时应看到：

- 目录名
- 文件名
- 文件大小
- 修改时间
- 删除状态

但此时不需要拉取文件内容。

### 6. 删除模型

- 删除文件或目录时，不直接物理删除历史链数据
- 第一版只写删除标记
- 本地目录树默认隐藏已删除对象
- 后续版本可扩展恢复能力

## 数据对象建议

第一版建议最少定义 4 类链上对象：

- `drive_dir`
  - 目录节点
- `drive_file`
  - 文件元数据节点
- `drive_chunk`
  - 文件内容分片
- `drive_delete`
  - 删除标记

## 目录树与文件对象语义

### 目录对象 `drive_dir`

建议至少包含：

- `ownerWalletId`
- `dirId`
- `parentDirId`
- `encryptedName`
- `createdAt`
- `updatedAt`
- `version`

### 文件对象 `drive_file`

建议至少包含：

- `ownerWalletId`
- `fileId`
- `parentDirId`
- `encryptedName`
- `size`
- `chunkCount`
- `contentRef`
- `contentHash`
- `createdAt`
- `updatedAt`
- `version`

说明：

- 文件名属于目录树索引
- 文件内容不包含在目录树对象里
- 浏览目录时，只需要目录对象和文件对象
- 下载文件时，再通过 `contentRef` 或 chunk 索引拉取内容块

### 内容块对象 `drive_chunk`

建议至少包含：

- `ownerWalletId`
- `fileId`
- `chunkIndex`
- `encryptedPayload`
- `payloadHash`
- `chunkSize`
- `compression`

### 删除对象 `drive_delete`

建议至少包含：

- `ownerWalletId`
- `targetType`
- `targetId`
- `deletedAt`

## 明确的实现边界

### 第一版要做

- 浏览器上传文件到服务器
- 服务器压缩、分块、加密并写链
- 目录树、文件名、文件索引上链且加密
- 节点自动同步自己的目录树和文件索引
- 不自动下载文件内容
- 服务器本地下载并自动解压
- 浏览器下载文件
- 删除标记
- 大文件上传进度

### 第一版不做

- 公共分享链接
- 他人文件浏览
- 浏览器端零知识加密
- 全网对象本地缓存
- 链上垃圾回收
- 多副本内容路由
- 文件协作编辑

## 仍需后续拍板但不影响当前需求成立的实现细节

### 1. 压缩粒度

建议：

- 整文件先压缩，再分块

原因：

- 恢复流程简单
- 内容校验清晰
- 与目录树元数据分离更自然

### 2. 目录树上链粒度

建议：

- 每个目录对象和文件对象单独上链

原因：

- 删除和更新更容易
- 第一版实现简单
- 不需要一次重写整个目录 manifest

### 3. 文件名加密范围

建议：

- 文件名全文加密
- 扩展名也不裸露

原因：

- 避免从扩展名直接泄露内容类型

## 推荐模块拆分

建议第一版拆成独立模块，不混入聊天模块：

- `drive_crypto_service.js`
- `drive_chunk_codec.js`
- `drive_manifest_protocol.js`
- `drive_index_runtime.js`
- `drive_index_store.js`
- `drive_upload_service.js`
- `drive_download_service.js`
- `drive_sync_service.js`
- `drive_browser_routes.js`
- `drive_local_fs_service.js`
- `drive_trash_runtime.js`

## 分阶段开发计划

### 阶段 1：定义网盘模块骨架

目标：

- 新网盘模块独立存在
- 不与聊天传输和聊天存储逻辑耦合

验收：

- 新模块文件可独立通过 `node --check`
- 现有功能不受影响

### 阶段 2：定义链上协议与本地索引结构

实现：

- `drive_manifest_protocol`
- `drive_index_runtime`
- `drive_index_store`

目标：

- 明确目录对象、文件对象、内容块、删除标记协议
- 本地可恢复目录树和文件索引

验收：

- 能创建目录对象和文件对象索引
- 能根据 `ownerWalletId` 重建自己的目录树

### 阶段 3：实现密钥与加解密服务

实现：

- `drive_crypto_service`

目标：

- 通过钱包能力解锁或派生 `driveMasterKey`
- 基于 `driveMasterKey` 派生 `dirKey/fileKey`
- 支持目录名、文件名、文件内容块的加解密

验收：

- 目录对象可加密/解密
- 文件对象可加密/解密
- chunk 可加密/解密

### 阶段 4：实现上传链路

实现：

- `drive_upload_service`
- `drive_chunk_codec`

目标：

- 浏览器可上传大文件到服务器
- 上传文件前先确保目录路径已存在并完成上链
- 服务器完成压缩、分块、加密和上链
- 上传过程可显示进度

验收：

- 文件不会挂到不存在的目录下
- 父目录链完整存在后才允许创建文件对象
- 大文件上传不依赖一次性读入内存
- 上传进度可见
- 上传后链上生成目录和文件索引对象

### 阶段 5：实现同步与恢复

实现：

- `drive_sync_service`
- `drive_index_store`

目标：

- 链扫描时只保留自己的目录树和文件索引
- 不自动下载文件内容

验收：

- 重启后可恢复目录树和文件名
- 其它用户的数据不会进入本地索引

### 阶段 6：实现服务器本地下载与恢复

实现：

- `drive_download_service`
- `drive_local_fs_service`

目标：

- 选择多个文件或目录后，服务器从链上拉取内容块
- 解密、组装、解压并恢复到服务器本地目录

验收：

- 文件内容正确恢复
- 本地目录结构与链上目录树一致

### 阶段 7：实现浏览器下载

实现：

- `drive_browser_routes`

目标：

- 用户可通过网页下载文件
- 目录下载可按需要打包

验收：

- 浏览器可下载单文件
- 浏览器可下载选中的目录内容

### 阶段 8：实现删除标记与目录过滤

实现：

- `drive_trash_runtime`

目标：

- 文件和目录删除只写删除标记
- 目录浏览默认隐藏已删除对象

验收：

- 删除后目录树立即收敛
- 内容历史仍保留

## 完成标准

第一版完成必须满足：

- 服务器可持有并恢复网盘解密能力
- 目录树和文件名加密上链
- 文件内容分块加密上链
- 同步时只恢复自己的目录树和文件索引
- 浏览目录不下载文件内容
- 支持服务器本地恢复下载
- 支持浏览器下载
- 支持大文件上传进度
- 删除使用删除标记
