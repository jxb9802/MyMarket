# CHAT_MODULE_EXECUTION_PLAN_V1

## 1. 目标

把聊天系统按独立模块方式落地，确保：

- 后台聊天服务独立
- P2P 传输模块独立
- 链上聊天与 P2P 聊天并存
- 前端统一聊天窗口事件驱动更新

## 2. 执行原则

- 先完成底层，再做界面
- 先完成独立模块，再做跨模块集成
- 先完成可测试路径，再做体验细节
- 每一阶段都要有独立可验证结果

## 3. 实施阶段

### 阶段 1：P2P 传输层定型

目标：

- 完成独立 `p2p transport` 模块
- 保持与聊天业务解耦

工作项：

- 固化统一协议
- 固化三条传输路径：
  - `direct`
  - `holepunch`
  - `relay`
- 加入正式身份校验
- 加入在线/离线拒聊
- 加入黑名单拒绝
- 加入 ACK 与去重
- 提供独立测试设备程序

完成标准：

- Linux 与 Windows 节点可独立验证直连、打洞、中继
- 能明确返回：
  - 接受
  - 离线拒绝
  - 黑名单拒绝
  - 失败原因

### 阶段 2：独立聊天后台服务

目标：

- 建立独立 `chat_domain`
- 聊天后台可单独恢复、存储、处理事件

工作项：

- 建立聊天线程存储
- 建立聊天消息存储
- 建立未读统计
- 建立好友存储
- 建立黑名单存储
- 建立聊天状态存储
- 启动期从数据库恢复
- 运行期只通过总线接收输入

完成标准：

- 不依赖页面运行
- 不直接读取其它模块运行态
- 数据可以独立恢复

### 阶段 3：链上聊天接入

目标：

- 让链上聊天先形成稳定闭环

工作项：

- 定义链上聊天消息格式
- 定义好友请求链上格式
- 定义好友同意/拒绝链上格式
- 链上消息解析入聊天域
- 订单聊天按 `orderId` 建线程
- 普通链上消息与 P2P 消息统一消息模型

完成标准：

- 链上好友请求可完成闭环
- 订单聊天可稳定展示

### 阶段 4：P2P 消息接入聊天域

目标：

- 让 P2P 传输正式进入聊天线程体系

工作项：

- `p2p.message.received` 接入消息入库
- `p2p.message.acked` 接入消息状态更新
- `p2p.session.*` 接入会话状态投影
- `p2p.path.changed` 接入连接状态显示
- 黑名单逻辑与聊天域保持一致

完成标准：

- 一个线程中可同时展示链上与 P2P 消息
- 每条消息正确保留来源和状态

### 阶段 5：好友系统

目标：

- 完成好友分组和请求流程

工作项：

- 发好友请求
- 同意好友请求
- 拒绝好友请求
- 好友组独立展示
- 非好友列表只保留最近 `5` 个

完成标准：

- 好友关系状态明确
- 好友组与普通联系人完全分离

### 阶段 6：用户发现与查询

目标：

- 支持查找新用户

工作项：

- 建立已上传个人信息用户查询接口
- 支持按钱包或资料字段查询
- 查询结果不自动进入主聊天列表
- 查询后可：
  - 发起新会话
  - 发起好友请求

完成标准：

- 能查到新用户
- 不污染最近联系人列表

### 阶段 7：聊天前端界面

目标：

- 实现统一聊天窗口

工作项：

- 主界面聊天按钮未读数字
- 好友组列表
- 最近 `5` 个非好友列表
- 用户查询入口
- 聊天窗口消息区
- 左右气泡布局
- 消息来源标记
- 每线程未读数字
- 状态显示区
- 状态切换和操作按钮：
  - 在线/离线切换
  - 连接测试
  - 好友操作
  - 黑名单操作

完成标准：

- 前端只通过事件驱动更新
- 不依赖轮询

### 阶段 8：本地存储治理

目标：

- 控制本地聊天存储规模

工作项：

- 统计聊天存储总量
- 设置 `100MB` 上限
- 超限后按最旧优先覆盖
- 黑名单消息不进入保留池
- 后续为图片/语音/附件预留扩展点

完成标准：

- 本地聊天存储不会无限增长
- 清理后索引仍一致

### 阶段 9：整体验证

目标：

- 形成可上线的第一版聊天系统

测试项：

- P2P 直连测试
- P2P 打洞测试
- P2P 中继测试
- 在线/离线测试
- 黑名单测试
- 好友请求链路测试
- 链上消息测试
- P2P 消息测试
- 未读数测试
- 切钱包隔离测试
- 存储上限覆盖测试

## 4. 自动执行顺序

推荐实际开发顺序固定为：

1. `P2P transport`
2. `chat_domain`
3. 链上聊天
4. P2P 接入聊天域
5. 好友系统
6. 用户查询
7. 前端界面
8. 存储上限
9. 回归测试

当前已经具备基础条件的部分：

- 独立 P2P 测试模块已可运行
- Linux/Windows 直连、打洞、中继测试已通过
- 聊天需求文档已初步收敛

所以下一步最适合直接进入：

- 阶段 1 收尾：把测试版 P2P 模块升级成正式聊天传输层
