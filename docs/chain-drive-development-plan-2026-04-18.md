# 链上网盘开发执行计划

日期：2026-04-18

状态：执行基线

关联需求文档：

- [chain-drive-requirements-2026-04-17.md](./chain-drive-requirements-2026-04-17.md)

## 总目标

把网盘模块改造成一套真正可用的“目录资源管理器 + 数据库索引 + 本地目录映射 + 链上内容恢复”体系：

- 目录和文件元数据存数据库
- 文件内容不进数据库
- 进入网盘只按目录逐层加载
- 内存只维护已加载目录对象
- 创建网盘目录时同步创建服务器本地目录
- 上传文件时先复制到本地目录，再加密分块上链
- 本地上传的文件默认就是“已下载”
- 本地文件被手动删除后，浏览器下载时自动从链上恢复

## 总原则

### 1. 数据库存索引

- 保存目录结构、文件信息、父子关系、下载状态、本地相对路径、删除状态
- 不保存文件内容和分块二进制

### 2. 文件内容只保存在两处

- 链上分块内容
- 服务器本地恢复目录里的真实文件

### 3. 网盘目录和服务器目录一一映射

- 创建网盘目录时，服务器本地也必须创建对应目录
- 网盘路径和服务器本地相对路径保持一致

### 4. 网盘打开时只加载当前层

- 首次进入只加载根目录
- 用户进入子目录时再加载下一层
- 可额外预加载下一层目录用于左侧树显示

### 5. 内存 runtime 只缓存已加载部分

- 数据库读一次后进入内存对象
- 后续优先用内存，不重复查库
- 变动通过事件同步更新数据库和内存

### 6. 浏览器下载必须支持自动恢复

- 本地存在就直接返回
- 本地不存在就自动从链上恢复，再返回浏览器
- 恢复后重新写回服务器本地目录，并标记已下载

## 执行阶段

### 阶段 1：把目录和文件元数据改成数据库存储

实现：

- `drive_index_store.js` 改为 SQLite 主存储
- 保存目录、文件、删除标记、任务、钱包网盘设置

数据库表至少包括：

- `drive_owner_settings`
- `drive_dirs`
- `drive_files`
- `drive_deletes`
- `drive_tasks`

验收：

- 可按 `parentDirId` 查询目录直接子项
- 可按 `dirId/fileId` 查询单项
- 可更新下载状态
- 不存文件内容

### 阶段 2：按目录分层加载 runtime

实现：

- `drive_index_runtime.js` 改成“已加载目录缓存”

职责：

- 缓存已加载目录
- 缓存目录子项
- 标记哪些目录已加载
- 目录切换时按需加载
- 左侧树同步当前目录

验收：

- 首次进入只加载根目录
- 双击目录时才加载下一层
- 同目录重复进入不重复查库

### 阶段 3：同步服务改成写数据库

实现：

- `drive_sync_service.js`

职责：

- 链上同步目录和文件对象
- 只写本地数据库
- 不在 `/api/drive/tree` 时全量 rebuild 全部对象
- 只同步当前钱包对象

验收：

- 重启后目录结构能从数据库恢复
- 打开网盘不扫描当前钱包全部对象

### 阶段 4：目录创建必须同步到服务器本地目录

规则：

- 创建网盘目录时：
  - 写数据库
  - 更新 runtime
  - 同时在服务器本地根目录下创建物理目录

验收：

- 新建目录后服务器本地立即出现对应目录

### 阶段 5：上传文件先落本地，再上链

固定顺序：

1. 确保网盘目录存在
2. 确保服务器本地物理目录存在
3. 将用户上传文件复制到目标目录对应的服务器本地目录
4. 从这个本地文件执行压缩、加密、分块、上链
5. 写文件元数据到数据库
6. 更新 runtime
7. 设置 `downloaded = true`

验收：

- 上传后服务器本地目录里立即能看到文件
- 上传后文件默认显示“已下载”

### 阶段 6：下载支持服务器恢复和浏览器自动恢复

规则：

- 下载到服务器：
  - 本地存在则直接确认
  - 本地不存在则从链上恢复，写回服务器目录，并标记已下载

- 浏览器下载：
  - 本地存在则直接返回
  - 本地不存在则自动链上恢复，写回服务器目录，再返回浏览器，并标记已下载

验收：

- 手动删本地文件后，浏览器下载仍能成功
- 自动恢复后状态从“未下载”变成“已下载”

### 阶段 7：已下载状态按本地文件实际存在判断

定义：

- 已下载：服务器本地对应文件存在
- 未下载：索引存在，但服务器本地文件不存在

验收：

- 手动删文件后状态会回落为未下载
- 浏览器下载恢复成功后状态重新变已下载

### 阶段 8：通过事件同时更新数据库和内存

建议事件：

- `drive.dir.created`
- `drive.dir.deleted`
- `drive.file.created`
- `drive.file.deleted`
- `drive.file.uploaded`
- `drive.file.downloaded`
- `drive.file.missing`
- `drive.tree.updated`

规则：

- 事件发生时同步更新：
  - 数据库
  - runtime 内存
  - 前端视图

验收：

- 新建目录、上传、删除、恢复后 UI 不需重开即可收敛

### 阶段 9：补齐前端资源管理器动作

前端必须具备：

- 设置目录
- 左侧目录树
- 右侧目录和文件统一内容区
- 目录在前，文件在后
- 文件按扩展名显示图标
- 列表 / 大图标两种视图
- 双击目录进入目录
- 左树跟随定位
- 创建目录
- 删除目录
- 上传文件
- 下载到服务器
- 浏览器下载

验收：

- 网盘界面可完整完成目录浏览和文件操作

## 最终验收标准

完成后必须满足：

1. 网盘目录和文件元数据存数据库，不再用全量 JSON 索引做主查询源
2. 文件内容不进数据库
3. 进入网盘只加载根目录，后续按层加载
4. 内存 runtime 只缓存已加载目录对象，不反复查数据库
5. 创建网盘目录时，本地对应物理目录也同步创建
6. 上传文件时先复制到本地目录，再压缩加密分块上链
7. 本地上传文件默认显示“已下载”
8. 手动删本地文件后，状态可回落为“未下载”
9. 浏览器下载在本地文件不存在时能自动从链上恢复
10. 恢复成功后自动写回服务器本地目录并变成“已下载”
11. 前端必须有：
   - 设置目录
   - 创建目录
   - 删除目录
   - 上传文件
   - 下载文件
   - 浏览器下载
   - 列表/大图标
   - 双击进入目录
   - 左树跟随定位
